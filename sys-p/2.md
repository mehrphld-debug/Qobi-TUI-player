## Section 3: Optimized Prompt — Full Version

```
Use the blueprint skill to plan: "Qobi — TUI Local Music Player in Rust (macOS + Arch Linux)"

Context:
- Greenfield Rust TUI player. No existing Cargo.toml (only maste1.md/master.md present).
- Vision: most beautiful/fast local-only TUI player. Opens instantly, find/select/play in <5s, foreground single-instance only, offline only, volume-only audio (use host output config).
- Design: fully transparent (no background), Apple + Notion philosophy, thin/elegant/premium, keyboard-first, mouse secondary, built-in help page, responsive layout.
- CLI: `qobi` (configured ~/Music dir), `qobi <dir>`, `qobi <file.mp3>`. Config in ~/.config/qobi/. Remember music dir between sessions.

Tech stack (pin before coding, use search-first skill to confirm latest):
- Rust edition 2021, ratatui + crossterm, rodio for playback + symphonia for decoding, lofty for metadata/cover art
- TOML config, no DB for v0.1.0 (file cache only)

Before executing, answer in blueprint:
1. rodio vs symphonia+cpal? lofty vs metaflac? ratatui version? Why?
2. Album art method: Kitty graphics + Sixel + block fallback? Matrix per terminal (iTerm2, Terminal.app, Alacritty, Kitty, WezTerm)?
3. Transparency implementation + fallback when unsupported?
4. Real-time equalizer: FFT bands count, analysis thread, mouse-hover interaction, disable flag?
5. Data structs: Track, Playlist, Config, PlayerState, EqState? Cache strategy?
6. Shortcut map avoiding terminal conflicts (propose vs Ctrl+P / Ctrl+X / Ctrl+C / double-backspace)?

Blueprint phases (each = 1 PR with /verify gate, use /save-session + /resume-session between):
- Phase 0: Research.md (competitors, Apple/Notion->TUI mapping, audio/TUI/image crates, scenario map)
- Phase 1: Architecture.md + Keyboard-Shortcuts.md + UI-Wireframes.md + Chunk-Map.md (A-J with deps/order)
- Phase 2: Chunk A (audio engine: load/play/pause/stop/seek/volume) + B (scan/metadata/art cache) + E (config + first-run setup) via /tdd
- Phase 3: Chunk C (ratatui transparent layout) + D (keyboard input) + F (art display) via /tdd
- Phase 4: Chunk G (sound-reactive EQ + hover + toggle) via /tdd
- Phase 5: Chunk H (playlist queue/select/shuffle/repeat) + I (settings) + search + error handling via /tdd
- Phase 6: Integration, perf (startup <300ms, idle CPU/memory baselines, large-dir scan), cross-platform matrix, docs (README, Architecture, agent-doc.md), release v0.1.0 (brew + AUR)

Workflow per phase:
1. /plan the phase referencing Architecture.md
2. /tdd — failing tests first (table-driven for handlers, golden for rendering where feasible)
3. Implement following existing patterns
4. /code-review via code-reviewer agent
5. /verify — cargo test + cargo clippy -- -D warnings + cargo fmt --check + manual terminal check

Acceptance criteria v0.1.0:
- `cargo test` green, coverage 80%+ on engine/config/playlist
- clippy clean, fmt clean
- Opens to music in <5s, startup <300ms on M-series + Arch reference
- Plays mp3/flac/wav/ogg/m4a; missing/unsupported/permission errors return to picker, never crash
- Transparent on at least iTerm2/Alacritty/Kitty + foot/WezTerm; art + EQ visible or graceful fallback
- Help page lists all shortcuts

Do not:
- Add streaming (Spotify/SoundCloud), networking, daemon/background service
- Add fancy DSP beyond volume + EQ viz
- Change CLI contract above without updating docs
- Introduce new audio/TUI crates without search-first comparison
```
