#  **Qobi — TUI Local Music Player**
## Complete Requirements Breakdown

---

##  **Main Idea**

**Qobi** is a TUI (Terminal User Interface) local music player designed for macOS and Arch Linux, written in Rust.

Core Vision:
- The most beautiful and fast TUI local music player
- Great design in both frontend and backend
- Fully local, lightweight, fast and powerful
- Opens instantly in terminal
- Users can find and select music quickly, play it, and get back to work both terminaly by selecting a dir or file and the TUI style
- Users can return at any time to check current playing music, see album cover, view equalizer animation, change music, or check playlist/music directory its open on the terminal window until close manualy (ctrl + c || double back space)
- no fancy sound settings ,only volume control! its work perfectly with the audio system and audio output machine and use the same config as the host system

Design Philosophy Foundation:
- Apple design philosophy
- Notion design philosophy
- Elegance and thinness are very important
- Simple, premium and obsessively perfect
- Transparent design matching transparent terminals

User Workflow:
1. Open in terminal → Find music or select multiple tracks → Play → Get back to work
2. Return anytime → Check current playing music → See album cover → View equalizer animation → Change music or check playlist/directory → Return to work
3. Handle all detailed usage situations with great, simple, fast solutions

## **Architecture and Design**

### **Design Foundation**

**Visual Design Philosophy:**
- Transparency mandatory (no background, must match transparent terminals)
- Album cover pictures displayed for each playing music
- Dynamic and colorful equalizer animation that reacts to sound and mouse hover
- Equalizer colors can be disabled in settings
- Apple & Notion design principles throughout

**Technical Architecture:**

Frontend:
- TUI interface built for speed and elegance
- Keyboard-driven primary interaction
- built in help page that can be open and see all the shortcuts and their tasks
- Minimal visual elements, maximum usability
- Real-time album artwork display ,random light color or random mathematic patterns (built in generated) by default for files that has no cover
- Animated equalizer visualization (sound-reactive)
- Mouse hover interactivity for equalizer

Backend:
- Rust for performance and reliability
- Local file system scanning and playback
- Audio file format support (all music/audio formats)
- Metadata extraction (cover art, track info)
- Equalizer audio processing
- Configuration management

Infrastructure:
- Cross-platform (macOS, Arch Linux)
- Lightweight memory footprint
- Fast startup time
- Directory-based music library management
- Transparent terminal integration

### **File Handling Architecture**

**Directory Management:**
- First-time setup: User inputs main music directory (e.g., ~/Music, ~/Documents/moosic, etc.)
- Configuration file stores selected directory for future sessions
- Support for custom directory paths

**Playback Options:**
- Specific file: `Qobi ~/Desktop/atish-soozi.mp3`
- Directory playback: `Qobi ~/Desktop/Music` (plays all audio/music files in directory)
- Default directory playback: `Qobi` (plays from configured main directory)

**Audio File Support:**
- Play any music and audio file format from any directory
- Metadata extraction for display
- Album cover picture extraction and display

### **Visual Components**

**Core UI Elements:**
- Currently playing track information
- Album artwork display (centered, prominent)
- Dynamic equalizer animation (reactive to sound and mouse)
- Playlist view
- Music directory/browser
- Playback controls indicator
- Time progress display

**Design Constraints:**
- Fully transparent background
- Minimal color palette (matching terminal theme)
- Elegant typography
- Obsessive attention to spacing and alignment
- Premium feel despite simplicity

## **Rules**

### **Design Rules**

1. **Transparency Rule**: No background color; must be fully transparent and match terminal environment
2. **Elegance Rule**: Every visual element must serve a purpose; no decoration for decoration's sake
3. **Speed Rule**: App must open and respond instantly; no perceived lag
4. **Simplicity Rule**: UI must be intuitive; user should understand usage without documentation
5. **Premium Rule**: Despite simplicity, feel should be premium and polished (Apple/Notion standard)
6. **Apple Philosophy Rule**: Prioritize usability over feature count; focus on doing one thing perfectly
7. **Notion Philosophy Rule**: Beautiful typography, breathing room, visual hierarchy clarity

### **Functionality Rules**

1. **Keyboard-First Rule**: All primary interactions driven by keyboard shortcuts; mouse as secondary
2. **Local-Only Rule**: At this stage, play only local files; no streaming (future: Spotify/SoundCloud)
3. **Directory Persistence Rule**: Remember selected music directory between sessions
4. **Audio Format Rule**: Support all common audio file formats
5. **Metadata Rule**: Extract and display album artwork, track title, artist, duration
6. **Equalizer Rule**: Display dynamic, sound-reactive equalizer animation; make disableable in settings

### **User Interaction Rules**

1. **Quick Access Rule**: Users should go from terminal open to playing music in under 5 seconds
2. **Context Switching Rule**: Users must be able to pause app, work, and return to music seamlessly
3. **Multiple Selection Rule**: Users must be able to select and queue multiple tracks
4. **Search Rule**: Users must be able to search within playlist or music directory quickly
5. **Playlist Management Rule**: Users must be able to view, clear, and manage current playlist

### **Technical Rules**

1. **Memory Rule**: Lightweight footprint; must not slow down system
2. **CPU Rule**: Efficient audio processing; minimal CPU usage during playback
3. **Cross-Platform Rule**: Must work identically on macOS and Arch Linux
4. **Configuration Rule**: Store settings in standard location (e.g., ~/.config/qobi/)
5. **Error Handling Rule**: Graceful handling of missing files, unsupported formats, permission errors not crashing the app, only back to the first stage, choose a music to play!

### **Scope Rules (Current Phase)**

1. **Local Only**: No streaming services at this stage
2. **No Network**: All functionality must work offline
3. **No Background Service**: Runs only in active terminal session and close everything has been used for working after closed.
4. **Single Instance**: Focus on single-instance operation (no daemon)

**Step 1.1: Competitive Analysis**
- Analyze existing TUI music players:
  - **kew**: Identify weak points, good points, design patterns
  - **cliamp**: Same analysis
  - **ncmpcpp**: Features, limitations, UI approach
  - **spotify-tui**: Design language, responsiveness
  - Others as discovered
- Document findings (strong features, weak areas, user pain points, design inspirations)
- Create comparison matrix

**Step 1.2: Design Philosophy Research**
- Deep dive into Apple Design Principles:
  - Clarity
  - Deference
  - Depth
  - Simplicity
  - Accessibility
  - Direct manipulation
- Deep dive into Notion Design Philosophy:
  - Breathing room
  - Typography hierarchy
  - Visual feedback
  - Consistency
- Map how these apply to TUI environment

**Step 1.3: Technical Architecture Research**
- Research Rust audio libraries:
  - `rodio` (audio playback)
  - `metaflac` / `metaflac-rs` (metadata)
  - `symphonia` (audio decoding)
  - Compare performance, features, maintenance
- Research TUI frameworks:
  - `ratatui` (formerly tui-rs)
  - `crossterm` (cross-platform terminal)
  - Compare rendering performance, features
- Research terminal capabilities:
  - Image/artwork display in terminal
  - Color depth and transparency
  - Mouse input support

**Step 1.4: User Scenario Mapping**

  - Creating playlists
  - Switching back to music while working
  - Viewing album artwork
  - Interacting with equalizer
  - Adjusting settings
  - Handling errors (missing files, unsupported formats)
  - Quitting and resuming
  - [Continue finding all realistic scenarios]
